# Nationals finals-qualification & awards — ported logic spec

**Status:** authoritative ruleset for the TS port. Distilled from the read-only reference repo
`jules-pierce/naigc-2024` (Python/pandas/pptx) so we never need to re-read the Python. Source files:
`meet.py`, `discipline.py`, `artistic.py`, `event.py`, `tnt.py`, `decathlon.py`, `omnithon.py`,
`constants.py`, and the per-discipline `config/<disc>/config.ini`.

Golden fixtures (the parity oracle) live in `tests/fixtures/nationals/`, generated by
`scripts/extract_nationals_fixtures.py` from Jules's 2024 & 2025 `data/` (inputs) + `solutions/`
(expected outputs) + `config.ini`. The TS engine in `src/nationals/` must reproduce `expected` exactly.

---

## 1. Domain vocabulary

- **Discipline:** WAG, MAG, TNT. WAG events = VT, UB, BM(=BB), FX. MAG events = FX, PH, SR, VT, PB, HB.
  TNT events = Tumbling, Trampoline, Synch Trampoline, DMT (each with its **own per-event level**).
- **Level (`CompLevel`):** WAG = XS, XP, XD, L9, Open. MAG = Dev, Int, Adv. TNT levels are per event:
  New Flyers, Intermediate Flyers, High Flyers. (Masters not in these fixtures.)
- **Placement category:** derived per athlete from `(Student: bool, Gender)`:
  - `Student` true → **Collegiate**, else **Community**.
  - `Gender == 'F'` → **Women+**, else (M, O, anything) → **Men+**.
  - The four: `Collegiate Women+`, `Collegiate Men+`, `Community Women+`, `Community Men+`.
  - `Mixed` is a **team-only** category (a team with both a Men+ and a Women+ scorer).
- **Scope:** the dimension a cutoff applies to — `Event`, `AA` (all-around), or `Team`.
- **Scoring precision:** all scores rounded to **3 decimals, half-up** (not banker's rounding).
  `round_score(x)` = `Decimal(str(x)).quantize(0.001, ROUND_HALF_UP)`. Replicate exactly — a 0.0005
  difference flips placements.

## 2. Input record shape (what the engine consumes)

Per athlete-row (one row = one athlete in one discipline), from the SF export:
`FirstName, LastName, Athlete_Email, Club_Name, Gender, Student(bool), CompLevel, Session`, plus per event:
- `<EV>_Score` (float), `<EV>_Event_Status` ∈ {`Included`, `Excluded`, `Scratched`}, `<EV>_Place_Eligible`
  (bool/0-1), `<EV>_SV` (start value). TNT events also carry `<EV>_Level` and synch carries
  `Synch_PartnerFirstName/LastName`. `AA_Score` is provided by SF (we re-derive & validate it).

Event abbr note: beam's input/status columns use **BM**, but its qual column is **BB?** and place column
"Beam Place". Vault/Floor reused across WAG+MAG; in combined events they get `_wag`/`_mag` suffixes.

## 3. Placement (per event AND All-Around)

`calculate_results_per_event` — for a given event/scope:
1. Group rows by **`(level, category)`** (TNT: by the event's own `<EV>_Level`, no category).
2. Sort the group by score **descending**.
3. Walk in order assigning places with **competition ranking (1,2,2,4)**: equal (rounded) scores share a
   place; the next strictly-lower score jumps to `place + count_of_ties`.
4. Only **eligible** rows get a place. Eligibility = `Place_Eligible` for that event is truthy AND (for
   finals) the athlete is in the finals place-eligible set. Ineligible/scratched rows get blank place.
5. **AA scope:** AA score = sum of the athlete's event scores (`round_score` each, then the sum). AA is
   place-eligible only if **all** sub-events are place-eligible. AA places computed the same way.
6. Synch Trampoline: partners share one placement; an `extra_places` index keyed by the unordered partner
   pair + level ensures both partners get the same place, and duplicate partner rows are merged in awards.

## 4. Finals qualification — "blue numbers"

Cutoffs come from `config.ini`, sectioned `"<Scope> <Category>"` (e.g. `[AA Collegiate Women+]`,
`[Events Community Men+]`, `[Team Mixed]`), each mapping `level → N`. Lookup: `get_blue_number(scope,
level, category)`. A row **qualifies** for an (event/AA/team) award when its place is a number and
`place <= N`. Stored as `<EV>?` / `AA?` / `Team?` = `Y` / `N`.

- **Finals vs non-finals levels:** `config.ini` has `[Finals Levels]` and `[Non Finals Levels]`. Finals
  levels (e.g. WAG XP/XD/L9; MAG Int/Adv) re-compete Saturday; awards come from **finals** results.
  Non-finals levels (e.g. WAG XS/Open; MAG Dev) award straight from **prelims**. The website "who made
  finals" export = qualifiers in finals levels only.

### 4a. 50% cross-club rule (`calc_50_perc_rule` + `add_places`)
For each `(level, category)` and scope, if the cutoff `N >= 6`:
- `min_alternate = floor(N/2)` ("at least half" rounds down).
- Among current qualifiers, find the most-represented club and its count `max_club_count`.
- If `(num_qualifiers - max_club_count) < min_alternate` **and** non-qualifiers remain, pull in the
  next-highest-scoring **place-eligible** athletes (sorted desc) whose `qual == N`, setting them to `Y`,
  decrementing the shortfall **only** when the pulled athlete is from a club other than `max_club`. Stop
  when the shortfall hits 0 (or candidates run out).

This guarantees finals fields aren't dominated by one club. Applied per event and AA (team scope too).

## 5. Team scoring (`calculate_score_per_team`, mixed teams)

- Group individual rows by `(Club_Name, level, category)`. Per event, take the **top 3** scores among rows
  with `Event_Status == Included` and nonzero score; a team needs **≥3 per event** or it scores 0 (gets
  dropped). Team score = sum over events of those top-3 sums (`round_score`).
- **Mixed teams:** grouped by `(Club, level)` ignoring category. Per event, top-3 of nonzero
  non-scratched scores; the used set must contain at least one Women+ (`Community/Collegiate Women+`) and
  at least one Men+ scorer, else the team scores 0. Mixed only computed for **prelims**.
- Exclude `Independent Community Athlete` / `Independent Student Athlete` "clubs" from team eligibility.
- Team places computed per `(level, category)` (Mixed is its own category), tie-aware. Team qual uses the
  `[Team <category>]` / `[Team Mixed]` cutoffs. A team whose every event was scratched → `Team? = N`.

## 6. Finals computation (Saturday)

Finals data file = same shape, but only finalists present/eligible. `finals.calculate_results(filter)`:
- `filter` = the **place-eligible** set read from the finals data file's `<EV>_Place_Eligible` columns.
- Places recomputed within `(level, category)` among place-eligible finalists, same blue numbers.
- Team finals: filtered by the **prelims** `Team?` qualifiers (only teams that qualified compete);
  mixed teams are **not** recomputed in finals (mixed is prelims-only).

## 7. Awards assembly (`create_awards_presentation`)

For each discipline, per event (and AA, and Team):
- **Non-finals levels:** pull rows from **prelims** results where `qual == Y`, sorted by place.
- **Finals levels:** pull rows from **finals** results where `qual == Y`, sorted by place.
- Rendered per `(event, level, category)` (4 category tables per level slide) and per team
  `(level, category)` incl. Mixed. Name shown as `First L.`; synch shows both partners.

## 8. Combined-discipline awards (prelims only)

- **Decathlon** (`decathlon.py`): athletes who did both WAG & MAG. `Overall Score = 2×WAG_AA + MAG_AA`
  (`round_score`). Level label = `"<WAG level>/<MAG level>"`. Placed top-3 overall **per level-combo**
  (blue number hardcoded `3`). Output cols: `Overall Score/Place/?`. **This is the real combined award.**
- **Omnithon** (`omnithon.py`): WAG+MAG+TNT. ⚠️ In Jules's code the Omnithon "Overall Score"/"Overall
  Place" columns are populated with an **eligibility boolean**, not a real composite score (the scoring
  line is effectively a placeholder). The 2024/2025 `omnithon_results.xlsx` therefore have `True` in
  those cells. **Port decision:** replicate decathlon faithfully; for omnithon, reproduce the fixture
  (eligibility flag) for parity and flag to rules@naigc.org that the real Omnithon formula is undefined
  in the reference tool — do **not** invent one without confirmation.

## 9. Validation report (`validate`)

Per discipline, produce error tables (empty = clean):
- **AA mismatch:** SF `AA_Score` ≠ sum of event scores (`round_score`).
- **SV cap:** per-level `[SV CAPS]` — any event whose Score or SV exceeds the cap.
- **Decimal places:** any score not a multiple of 0.001.
- **Prelims included:** an event with a nonzero score but `Event_Status == Excluded`.
- **Finals included / team finals:** team must have exactly 4 included per event (too many / not enough /
  missing scores).
- **Prelim-qual vs finals-eligibility:** for finals, an athlete `Place_Eligible` in finals must have been
  a prelims qualifier and vice-versa (`validate_place_eligible_vs_qual`).
- **TNT syncro:** partner pairs must both appear, at the same level, with equal scores.

## 10. Mapping to the UCG platform (for Phases 1+)

The engine is written against **generic level/category strings + a config object**, so the pure core is
platform-agnostic and tested directly against Jules's fixtures (his level codes + his config.ini). The
platform adapter (Phase 4) builds engine input from `Athlete` (`gender`, `studentStatus` →
`deriveCategory`), `Registration` (`levelId`, `events`), `Score` (`final`, `sv`, a scratched/included
flag), and `MeetSession.phase`. Platform level ids (`wag-silver/plat/diamond/l9/open`, `mag-dev/int/adv`,
`tnt-new/int/high`) map to Jules's codes (XS/XP/XD/L9/Open, Dev/Int/Adv, New/Intermediate/High Flyers);
the admin-entered `NationalsConfig` supplies cutoffs + the finals-level set keyed by platform level id.

## 11. Known reference-tool bugs (carry the platform's fixes, assert divergence in tests)

The platform already fixed several MAG calculator bugs during the native score-entry port (see the
score-engine work). Those are in **score computation**, upstream of this qualification logic, so they
don't affect these fixtures. Within this logic, the only flagged anomaly is the **Omnithon placeholder
score** (§8). Any other divergence from `solutions/*.xlsx` is a port bug until proven otherwise.
